# Decisions

Each entry records what was decided and why. Newest entries go at the bottom. All of these come from the design discussion of 2026-10-07, which was reviewed by Claude Fable at each step.

| # | Decision | Why | Rejected alternatives |
|---|---|---|---|
| D1 | **Two sides: tailnet writer(s) and a public reader.** | The tailnet is trusted; the internet isn't. | A single app with auth everywhere (needless friction for a solo tailnet) |
| D2 | **The tailnet is trusted.** No auth on writers. | The user is the only person on the tailnet. | — |
| D3 | **The public side is read-only forever and never accepts uploads.** | Keeps the attack surface minimal. Comments may come later, but uploads never will. | — |
| D4 | **Private by default. Public access only through grants, starting with share links. IDs are never credentials.** | IDs leak through logs, screenshots, and chat, and can't be revoked. | Unguessable URLs as access control; auto-publishing |
| D5 | **The cloud holds everything, private content included.** | The user's machines aren't highly available, and losing the DB isn't acceptable. | Local source of truth plus a publish-only bucket |
| D6 | **The public reader is a server, not a static bucket.** | Passwords, revocable tokens, expiry, and audiences all need a check on every request. | A static bucket behind a CDN (Fable's round-1 suggestion) |
| D7 | **The cloud DB is Turso, using Turso Sync** (`@tursodatabase/sync`). | Local reads and writes with push/pull; documented multi-writer support (last-push-wins; spike S1 showed updates to different columns merge); the user's preference for managed SQLite. | Embedded replicas (writes go to the cloud, so they fail offline); libSQL `offline: true` (beta, no conflict resolution); Postgres; plain SQLite |
| D8 | **Blobs go in Cloudflare R2** (free plan, private, Standard storage class). | Free egress, S3-compatible, conditional PUT, and a native Workers binding. | — |
| D9 | **TypeScript.** The writer runs on Node 24 (LTS); the reader runs on Workers. | Turso's TypeScript sync SDK is the most complete; the MCP TypeScript SDK is the reference implementation; AWS SDK v3 is the documented way to use R2. Bun is out because Turso Sync isn't documented for it. | Go (`tursogo` needs no cgo, but has no `transform` hook and thinner docs) |
| D10 | **The design must allow multiple writers.** | Future: more machines, maybe Kubernetes. | A single-writer-only design |
| D11 | **Insert-only tables.** The only update is collection title and metadata. | Under last-push-wins, insert-only rows with unique keys can't conflict. | — |
| D12 | **No `seq` column.** Revisions are ordered by ID; `#N` is computed for display. | Two writers would both choose the same `seq`. | A unique `(collection_id, seq)` |
| D13 | **Soft delete is a tombstone table,** not a `deleted_at` column. | Keeps deletion state apart from the mutable title and metadata. S1 showed updates to different columns merge, so a `deleted_at` column would probably also survive a title edit. The separate table is kept because it is cleaner and insert-only. Undelete races remain untested. | A `deleted_at` column on `collections` |
| D14 | **Upload the blob before inserting the row.** | The cloud never references missing content. | Readers tolerating missing blobs |
| D15 | **A local write queue in a separate `queue.db`, retrying every 5–10 min, giving up after 72 h.** | Writes succeed and render during internet or R2 outages. Turso Sync can't exclude tables, so the queue can't live in the synced DB. | Requiring the internet for writes; retrying forever; giving up after 50 attempts (≈6 h, too short) |
| D16 | **IDs are TypeIDs** (`col_`, `rev_`, …; UUIDv7 in base32), with no env segment. | You can tell an ID's type from the ID itself, and IDs are time-sortable. An env segment can't prevent cross-environment mistakes; the environment guard does. | cuid2 (not sortable), `<prefix>_live_<id>` |
| D17 | **Public IDs are 12 base32 characters derived from a hash of the ID.** | Short URLs. A retried revision on two writers yields identical rows, not two URLs. | Random public IDs; exposing IDs in URLs |
| D18 | **Revisions are immutable and kept forever. "Latest" by default, with a revision picker.** | History is valuable, and content addressing makes it cheap. | Editing in place; retention limits |
| D19 | **`add_revision` defaults to merge mode.** | Agents usually change one or two files. | Replace as the default |
| D20 | **Shares follow the latest revision by default.** Sharing from a pinned revision pins it. | Matches the user's intent. Copying the URL you're viewing gives the right behavior. | Always pinning |
| D21 | **MCP and HTTP API on day one. No CLI.** The MCP server is a local stdio process that reads files by path. | Agents are the main writers, and base64 file contents in tool arguments don't scale. | A remote MCP over HTTP only; a watched folder; CLI-first |
| D22 | **No slugs.** `create_collection` returns an ID, and edits require it. | Simpler; agents carry the ID. | Stable human slugs |
| D23 | **No separate content origin on the tailnet.** | All content comes from the user's own agents, so the risk is acceptable. | Sandboxed second origin |
| D24 | **The public reader runs on Cloudflare Workers at `waypoint.pingstash.com`.** | R2 proximity, free egress, edge cache, and built-in protections (Turnstile, rate limiting, WAF). D38 specifies the read-only S3 API connection. | Railway (egress fees, always-on container, more to build by hand) |
| D25 | **Markdown is pre-rendered by the writer into renditions**, keyed by source hash and renderer version. | Workers' 10 ms CPU limit, instant tailnet renders, and renderer upgrades never touch revisions. | Rendering on request |
| D26 | **Access logs go to Workers Analytics Engine.** | The reader's DB token stays read-only. | Logging to the main DB |
| D27 | **Additive-only migrations.** | Turso Sync currently has bugs around renaming and dropping columns. | — |
| D28 | **No storage cap for now.** | R2's free tier is generous, and overage is cheap. | Hard cap at 9 GB |
| D29 | **Four sync states: `pending`, `committed`, `synced`, `failed`.** | "Committed" (local DB plus bucket) is not the same as "in the cloud DB". Agents and the user need to know when a write is fully durable. Uses the "synced" wording the user preferred over "published". | Three states (which over-promised durability) |
| D30 | **Clients may mint `col_` and `rev_` IDs.** Revision IDs use `max(now, parent + 1 ms)`. | Makes retries idempotent, including for `create_collection`, and tolerates clock skew between machines. | IDs minted only by the writer (a retry after a timeout returned a 409) |
| D31 | **Renditions are self-contained** (inlined CSS and highlighting). Mermaid is deferred. | They work on the tailnet without internet access, and the reader only streams. | CDN-hosted assets |
| D32 | **Purge is resumable and single-writer only in phase 1.** | Multi-writer purge needs markers and a GC grace period, to be designed before a second writer goes live. | Building multi-writer purge now |
| D33 | **`PRAGMA foreign_keys` is OFF on the synced DB.** The committer enforces invariants. | Rows pulled from other writers can arrive in any order. Confirmed in S1: pulls bypass FK enforcement even when it is on. | FK enforcement |
| D34 | **`queue.db` uses `@tursodatabase/database`** (same engine, no sync), in a separate file and connection. | Spike S2: it coexists with the sync DB in one process and has the same async API. | `node:sqlite` (viable, but a second SQLite implementation) |
| D35 | **Constraint failures on push are surfaced, never ignored.** Pull, retry, then report. | S1: a `UNIQUE` violation fails the whole push, and a pull can replace the local row with the remote one. | Silently retrying |
| D36 | **The MCP tarball is a stable launcher that fetches the server bundle from the writer at startup**, with a cache and an embedded fallback. | npx caches tarball URLs forever, and content-hashed URLs broke configs on every change. The user requires configuring once, with updates flowing automatically. | Hashed tarball URLs (configs break or need editing on every change); a plain stable tarball (agents stuck on stale code) |
| D37 | **The writer is reachable only through its Tailscale sidecar, not from the plain LAN.** | The writer has no auth, and the trust boundary is the tailnet, not the home network (guests, IoT). The HTTPS certificate and CSRF origin checks are tied to the tailnet hostname. | Publishing a LAN port |
| D38 | **The reader reads blobs over the S3 API with a bucket-scoped, read-only R2 token, not an R2 binding.** | R2 bindings can't be permission-scoped, so a binding could write. With read-only credentials (R2 and Turso), a bug in the reader still can't modify anything. Egress is free either way. | An R2 binding guarded by code and lint |
| D39 | **A dev reader (`waypoint-dev.pingstash.com`, dev DB and bucket) runs alongside prod.** | Share links and the reader can be tested end to end without touching prod data. It's deny-by-default like prod. | Testing against prod only; `workers.dev` |
| D40 | **Raw public content uses a per-revision derived capability, not the share token.** The shell stays tokenized; its iframe uses an HMAC over the share-link ID and revision public ID. Raw responses require revalidation and use `private, no-cache`. | Agent HTML can read its own URL and may run third-party scripts. A leaked raw URL should grant only the revision being shown, and only while the link remains active and that revision is allowed. | Putting the full share token in iframe URLs |
| D41 | **Only denied public-reader requests consume the rate-limit binding.** An isolate keeps a bounded 60-second IP block after the binding rejects a denial; blocked and ordinary denials use one 404 response. | A legitimate document can load more than 30 images in a minute from one IP. Charging successful requests would lock out its viewer. | Counting every protected request |
| D42 | **No manual theme toggle; the shell and documents follow the OS colour scheme.** | Renditions run in an iframe (sandboxed in public) and can't follow a shell toggle, so a toggle would split the page into two themes. | A light/dark switch in the shell |
| D43 | **The share dialog defaults to "Only #N" (a pinned snapshot).** "Latest" shows an explicit "every future revision, by any agent" warning. | Publishing future agent output with no review step should be a deliberate choice, not the default. | Defaulting to Latest (phase 2's behaviour) |
| D44 | **Moving a collection to Trash doesn't revoke its links.** Tombstones already 404 every link; restoring asks before reactivating them and offers "Restore, revoke the links". Links can be revoked while in Trash. | Trash should be reversible without silently changing who can read what later. | Auto-revoking on delete |
| D45 | **One sans reading face (system UI stack) plus mono; no webfonts.** | A serif reading face rendered inconsistently across operating systems and made four voices with sans tables and mono code. | A serif document face |
| D46 | **Prefer native web platform primitives in the viewer.** Popovers with CSS anchor positioning, `<dialog>` opened by invoker commands, `<form method="dialog">` cancels, `<details>`, `:has()` for live form states, and `@starting-style` transitions (D51). Script only syncs the iframe URL, copies, sends fetch mutations, and handles shortcuts. | Less code to break, keyboard and accessibility behaviour for free, and pages that work without script. | Hand-rolled menus, focus traps and positioning |
| D47 | **Diffs and Changes-page Markdown run under explicit budgets, off the event loop.** Every jsdiff call has an edit-length cap and a time budget, word highlights and similarity pairing are capped, inputs over 32 KB are diffed in a worker thread that's stopped after 4 s, and changed blocks are rendered to HTML in that worker within 1 s (longer or late blocks show their source). A diff that hits a limit is `truncated` with a reason, and the page offers both versions instead. | Diffing and Markdown parsing are superlinear on some inputs, and the Changes page is a plain GET that any page could trigger with an `<img>`. A 160 KB one-line JSON file once held the writer for 64 s, including `/healthz`. | Unbounded inline diffs; per-request authentication for GETs |
| D48 | **A share link's expiry may be extended (moved later, never earlier) by updating `share_links.expires_at`; revocation and a never-expiring state are final.** A restore `--merge` keeps the later of the two expiries, where never expiring (null) counts as latest, so null on either side wins, and revoked stays revoked. | Keeping a review link alive shouldn't require minting a new token and resending it. Extension only widens access in time, as the owner chose, and can't resurrect a revoked or expired link. Taking the later expiry on merge means a restore never undoes an extension recorded on either side, and never extends past what one side recorded. | A new link per extension; letting the expiry move earlier (revocation already covers "stop now") |
| D49 | **PR previews are Worker Previews of the production reader Worker `waypoint-reader`, using the prod read-only reader credentials, on its `workers.dev` subdomain, and only behind Cloudflare Access (owner only).** Each same-repo PR gets `pr-<number>-waypoint-reader.seancassiere.workers.dev`, uploaded from the self-hosted runner and deleted on close. Previews have their own Analytics Engine dataset (`waypoint_access_preview`) and rate-limit namespace. **They're never enabled on the custom domain `waypoint.pingstash.com`**, which stays public, production only and without Access. Enabling `workers_dev` and `preview_urls` on the prod Worker is safe only because the same Access app covers those hostnames. | Reviewing a reader change against real content and real share links before merging, without a second copy of prod data. Previews of the prod Worker share its account, compatibility settings and data, so they behave like production; read-only credentials (D38) mean PR code can't modify anything. Access keeps unreviewed code and every prod document it can read away from the public, and the preview script refuses to leave up a preview that answers without it. Running on the self-hosted runner means a pushed branch can run code with production credentials before review; that's accepted because only the owner can push (see [trust-model.md](trust-model.md#deploy-pipeline)). | Previews of the dev reader (dev data doesn't show real documents or links); previews on `*.waypoint.pingstash.com` (a custom domain previews would have to stay out of search indexes and be put behind Access, next to the public production hostname); public preview URLs; uploading from GitHub-hosted runners (the deploy token and reader credentials would have to become GitHub secrets, which the trust model forbids) |
| D50 | **Share tokens are deterministic: `wps_` + base64url(HMAC-SHA256(key, `"waypoint/share-token/v1\n"` + link ID)), with a writer-only key (`WAYPOINT_SHARE_TOKEN_KEY`).** The label separates this use of the key from any other, and a new version would mint different tokens. The database still stores only `sha256(token)`, and the reader is unchanged. The writer re-derives a link's URL whenever the owner asks, and reports null ("URL unavailable") for links created before this (random tokens) or under another key. The key is needed only to create links and show URLs; listing, extending and revoking work without it. | The public URL isn't a secret from the owner, who wants to copy it again later. A leaked database alone still yields no working URLs; any writer holding the key can reproduce them. Revoking must never depend on a secret being configured. | Storing the token (a database leak becomes working URLs); encrypting tokens at rest in the database (the same key management plus ciphertext synced to Turso and snapshots); showing the URL once at creation (the owner found it hostile); an unlabelled HMAC over the bare link ID (no domain separation); a previous-key fallback so URLs survive a rotation (deferred: a rotation is for a leaked key, whose links should be recreated anyway) |
| D51 | **Motion is limited to opening and closing popovers, dialogs and the panel sheet, and to control state changes (hover, pressed, toggled, Copied): CSS transitions with `@starting-style`, at most 150 ms, none under reduced motion. No view transitions anywhere, writer or public shell.** Every menu is a `popover="auto"` that light-dismisses, including on a press inside the document iframe (same-origin frames report presses and Esc; other frames blur the window). Each popover is a positioning shell whose `.mbox` child is the visible box, so named `@position-try` placements plus anchored container queries (`@container anchored(fallback: …)`) give each placement its own `transform-origin`; a script sets it where those queries aren't supported. Below 600 px (phones), menus are bottom sheets over a tinted scrim; from 600 px (the iPad mini's 744 included) they stay anchored. On touch screens a transparent scrim takes the tap that closes a menu, so it can't also follow a link in the document; mouse clicks pass through. Choosing a menu item closes its menu. | The owner found page-level animation distracting and saw menus that didn't close on outside clicks: the iframe swallows the press. `@position-try` can't set `transform-origin`, so the per-placement origin needs the anchored query on a child. A popover's own `::backdrop` never takes pointer events, so a sheet's scrim must be a real element, or a tap that closes the sheet also activates what's beneath. | Cross-document and same-document view transitions (the previous design); a scrim for mouse pointers too (it would swallow a click on another menu's trigger); bottom sheets up to 760 px (the iPad mini would lose anchored menus); computing every origin in script |
| D52 | **Turborepo (pinned) runs the repo's tasks, and CI shares a signed Vercel remote cache. Deployed artifacts never come from the cache.** Each package has a `build` script; lint, typecheck, format check, tests and browser tests are root tasks that depend on every package build (since D53, typecheck and tests run per package from source, and lint needs no build). Tasks are cached by declared `inputs`, dependencies and env (strict env mode), and `remoteCache.signature` makes turbo sign uploads and reject unsigned or tampered downloads. `pnpm check` runs the tests in a second turbo invocation, after lint and typecheck, and the CPU-budget and timing tests in a third (`turbo run test:timing --concurrency=1`), one package at a time, so they never share the machine with other work. The writer image builds from source with turbo's caches off, and the Deploy and Preview workflows build the reader with plain `pnpm --filter`. | Parallel CI jobs each rebuilt the whole workspace, and local runs repeated work that hadn't changed. turbo builds each package once per input change and lets every CI job, and the next run, reuse it. The cache credentials only reach the cache, and keeping deploys off it means a cache entry can at worst skip a CI check (accepted in [trust-model.md](trust-model.md#deploy-pipeline)), never ship code. Signing guards against corrupted or substituted artifacts from the cache server. | Plain pnpm scripts (no caching, every job rebuilds); Nx (more machinery than six packages need); a GitHub Actions cache of `.turbo` (saved only when a job ends, so parallel jobs of one run can't share it, and scoped per branch); letting the Docker build use the remote cache (would put cache contents into the production image) |
| D53 | **tsdown bundles the libraries, the writer and the MCP server; TypeScript only type-checks. Workspace packages resolve to their source for typecheck, lint and tests (the `@waypoint/source` export condition), and to `dist` at runtime and in bundles. The MCP launcher stays on esbuild.** Libraries (`core`, `ui`, `render`) build unbundled ESM with `.d.ts` from oxc, which needs `isolatedDeclarations` (explicit types on exports). The writer bundles into `dist/main.js` plus its two worker-thread entries, inlining `@waypoint/*` and keeping npm dependencies external (the writer declares them, checked at build time). Relative imports name the `.ts` file and all source uses only erasable syntax (`erasableSyntaxOnly` in the base tsconfig, so anything else fails typecheck), so Node 24 runs the source directly, which the worker threads and browser suites do. Tests live in their packages; the timing tests are their own turbo task (`test:timing`) that runs alone; cross-package tests and checks of built artifacts live in `tests/` (`@waypoint/integration-tests`). The image is built from a `turbo prune --docker` of the writer and the MCP package. | `tsc -b` emit made every test, lint and typecheck wait for a full build, and the writer image shipped `src/`, per-file `dist/` and the workspace packages' own installs. tsdown (rolldown) bundles in well under a second per package and oxc generates declarations without the type checker; its TS 7 (`tsgo`) declaration path is experimental, so `isolatedDeclarations` keeps oxc in charge. The source condition makes tests and type-aware lint independent of builds without path aliases, while runtime code still exercises exactly what ships. The launcher is cached by npx indefinitely, so its build must not change at all; it was byte-identical as of D53 (D54 then changes one condition, for the plain-HTTP warning's opt-out). `turbo prune` replaces a hand-maintained `COPY` list and a lockfile workaround. | Keeping `tsc -b` (slow, needs a build before anything else); tsdown's `tsgo` declaration generator (experimental under TS 7); path aliases or project references instead of an export condition (references need `composite` and emit, and aliases diverge from runtime resolution); moving the launcher to tsdown (any change to it reaches machines only after their npx cache is cleared); bundling the writer's npm dependencies too (native Turso modules must stay external, and the image already installs production dependencies) |
| D54 | **Runtime config doesn't assume the owner's deployment. The bucket can have any name: an environment marker in it (`meta/environment.json`), written on first use when missing and checked before every writer's first bucket request, replaces the `R2_BUCKET == waypoint-<env>` rule. Any S3-compatible store works (`WAYPOINT_S3_ENDPOINT`, `WAYPOINT_S3_REGION`, path-style), with the `R2_*` names kept. `WAYPOINT_SYNC=off` (local-only mode) is allowed in prod, with a persistent no-durability warning; a data directory can't switch sync modes. `WAYPOINT_ENV` stays required. Writer and reader report the release version (root `package.json`) and build commit (`WAYPOINT_BUILD_SHA`) on their health endpoints, additively.** The MCP launcher gains one condition: `WAYPOINT_MCP_ALLOW_HTTP=1` silences its plain-HTTP warning for any host, and `*.ts.net` stays exempt. | Adopters name buckets their own way and may not use R2, or any cloud at first. The naming rule was a proxy for "don't point dev at prod"; the cloud DB's `meta.environment` already guards the DB, and the bucket marker guards the bucket directly. Treating a missing marker as "write it" keeps the owner's existing `waypoint-dev` and `waypoint-prod` buckets working with no migration. Local-only mode trades durability for zero setup, so the trade is shown wherever status is; flipping a synced replica to local writes would fork it from the cloud DB. A default `WAYPOINT_ENV=prod` would also default the data directory to the prod one. The version is a source constant (checked against `package.json`), so source runs, the bundles and the Worker all know it without build steps; health bodies keep their old contracts because deploy gates compare them. The launcher change is a single env check with `LAUNCHER_API` unchanged; launchers already in npx caches keep warning until the cache is cleared. | Keeping the naming rule (forces the owner's naming on everyone); a marker that fails when missing (breaks existing buckets); generic `WAYPOINT_S3_*` names for the credentials too (two names for one setting); refusing sync-off in prod (blocks the simplest self-host); defaulting `WAYPOINT_ENV` to prod; the version in the reader's health body (breaks `== ok` smoke checks); a JSON import of `package.json` (pulls the whole manifest into every bundle and needs per-bundler handling) |
